# Audit — August 2026: findings and resolutions

A three-way code audit (capture, viz, analyze/core) reviewed the codebase for
observability, logging, tracking gaps, profiling readiness, and CPU/performance.
~80 findings were produced; this document records what was fixed and what was
deliberately deferred. Line references are to the pre-fix code.

## Workspace & core (shared contract)

| Finding | Resolution |
|---|---|
| No profiling affordance: release builds had no debug symbols | **Fixed** — `[profile.profiling]` (release + symbols) and `codegen-units = 1` on release in the root `Cargo.toml`. Build with `cargo build --profile profiling` for flamegraphs. |
| Config accepted typo'd keys silently (`mouse_dpi` → every cm metric quietly wrong) | **Fixed** — `deny_unknown_fields` on `AppConfig` and every sub-struct; unknown keys are now a parse error. |
| No config validation (negative CPI → inf cm; `window_ms=0` → datagram per event; `max_events=0` → panic) | **Fixed** — `AppConfig::validate()` runs on load: positive CPI/sens/coeffs, window ≥ 1ms, `1 ≤ max_events ≤ MAX_EVENTS_PER_BATCH`, `ring_capacity ≥ max_events`, brokers non-empty when Kafka enabled. |
| Multiple pointing devices indistinguishable (trackpad silently pollutes CPI-derived metrics — unrecoverable retroactively) | **Fixed (wire)** — `SessionConfig.devices: Vec<String>` + `RawEvent.device_ix: u8`. Capture populates them; old recordings default to empty/0. |
| Horizontal wheel (`RI_MOUSE_HWHEEL`) silently discarded | **Fixed (wire)** — `RawEvent.wheel_h: i16`. |
| Absolute-motion frames counted locally but never recorded on the wire | **Fixed (wire)** — `Batch.abs_frames_since_last: u32`. |
| Anchor taken from two unbracketed clock reads, uncertainty unrecorded | **Fixed (wire)** — `SessionConfig.anchor_uncertainty_us` records the QPC/UTC/QPC sandwich half-width; capture measures it. |
| JSON wire cost ~71 B/event; `null`s serialized for absent options | **Improved** — zero-valued `buttons`/`wheel`/`wheel_h`/`device_ix` and `None` cursor/game fields are omitted; a typical motion-only event is now ~45 B. Consumers treat missing fields as 0/absent. Full binary schema remains deferred (below). |
| Worst-case batch could exceed a UDP datagram with the new fields | **Fixed** — `MAX_EVENTS_PER_BATCH` 512 → 448; the core test asserting a worst-case batch fits the datagram budget still enforces this. Cap only binds above ~17KHz. |

## Capture agent (crates/capture)

All 22 findings fixed (97 tests, clippy clean).

**Operational correctness**
- UDP `WSAECONNRESET` (viz not running — the default state) no longer warns per batch: counted as `udp_unreachable`; all sink failures rate-limited to one warn per sink per 10s with a suppressed count.
- Dead-capture detection: `capture_alive` flag — if T1's message loop dies, the agent shuts down loudly instead of running as a zombie. `idle_for_s` in stats distinguishes "idle mouse" from "capture broken".
- Both shutdown hangs fixed: HWND handoff via atomics with a `PostThreadMessageW` fallback; Kafka drain bounded by a 3s timeout with an abandoned-envelope count.

**Tracking (previously unrecoverable)**
- Devices enumerated at startup into `SessionConfig.devices` (index 0 reserved as "unknown"); every event carries `device_ix`, so a trackpad can no longer silently pollute CPI-derived metrics.
- Horizontal wheel captured (`wheel_h`); absolute-motion frames now on the wire per batch; pointer-lock transitions logged.
- Anchor taken as a QPC/UTC/QPC sandwich with recorded uncertainty; drift re-measured every 60s (logged in ppm, `anchor_drift_us=N` marker emitted past ±200µs).
- Config-file mtime watch: mid-session changes are validated, diffed into the log, and recorded as a `config_changed` marker; `WM_DISPLAYCHANGE` refreshes monitor info.

**Observability**
- Zero-allocation 32-bucket log2 latency histogram: `capture_to_ship_us` p50/p99 (and ship-tail p99) in the 5s stats line — the pipeline's first latency metric.
- Ring high-water sampling (early warning long before drops), JSONL flush-time max, `udp_oversized`, edge-triggered Kafka-drop warnings (0→dropping and recovery, never per-drop).
- The 5s stats line is now 22 structured tracing fields (including `session_id`) instead of one pre-formatted string.

**CPU**
- T2 parks and is unparked by T1 on the ring's empty→non-empty edge (one relaxed load per event on the hot path); park timeout tracks the remaining batch window (0.5–25ms), which also improves first-event latency. Main thread and T3 wait on a shutdown condvar — idle wakeups largely eliminated.
- Context snapshot moved out of the 333/s loop into the flush path and made `Arc` (no per-iteration mutex + String clone).
- T1's counters are cache-line-isolated (`#[repr(align(64))]`, layout-asserted by test) with relaxed stores instead of RMWs.
- Serialize-once: one JSON encode per batch into a reused buffer shared by all sinks; the Kafka channel carries `Arc<str>` payloads.
- Kafka: zstd compression + 25ms linger via the batch producer (produces coalesced through a bounded `JoinSet` so the linger actually batches).
- T1 runs at `ABOVE_NORMAL` priority; process opts out of EcoQoS power throttling so P/E-core parking can't starve capture.
- Foreground process name re-resolved only on PID change (~14,400 handle opens/hour → ~one per alt-tab).

## Viz (crates/viz)

All 22 findings fixed (52 tests, clippy clean; behaviors verified in a live browser session).

**Bugs**
- Hidden-tab memory leak: ingest hard-caps the event backlog (~2× the live window), a `setInterval` trim survives rAF suspension, and catch-up is bounded per tick — verified: 150k events ingested with a hidden tab stayed bounded, and returning drains without freezing.
- Capture-agent restart: a `session` envelope with a new id fully resets the engine before adopting the new anchor (no more mixed timelines).
- Scrubbing: forward seeks never re-integrate; backward seeks restore from 10s integrator checkpoints — verified bit-identical to full re-integration, cost now bounded by checkpoint spacing rather than session length.

**Latency (measured for the first time, and improvable)**
- End-to-end latency tile in the page (`anchor.utc_us` now used), bridge-side p50/p99 in the log, `/api/stats`, and a pushed `viz_stats` frame — observed loopback bridge latency p50 0.2ms.
- The 55ms smoothing buffer is now a 10–200ms slider (persisted); canvases use `{alpha:false, desynchronized:true}`, removing a compositor frame.
- New stat tiles: lag-behind-live (red > 250ms) and render FPS (red when below ~0.8× refresh).

**CPU**
- Dirty-flag rendering: zero draws when nothing changed (verified 240 idle frames → 0 draws) — previously the page full-redrew both canvases every frame forever.
- Event timeline converted to typed-array columns and trails to fixed ring buffers: no per-event object churn, no per-frame `splice`.
- Tokio trimmed to 2 worker threads (and features narrowed from "full"); transport-bar DOM writes throttled to 100ms; broadcast channel 1024→256 with `Arc<str>` payloads and a tag-only serde probe instead of full envelope parses.

**Scale**
- `/api/session/{id}` streams from disk (with Content-Length) instead of reading whole files into memory; the page loads replays via a streaming reader with progress, feeding typed arrays directly — hour-long sessions no longer risk tab OOM.

**Observability/tracking**
- Bridge health visible in the page (datagrams/s, parse errors red when nonzero) without polling; first rejected datagram logged at warn with a sanitized payload prefix, rate-limited per reason.
- `seq_no` gaps tracked as a separate "lost batches" stat (transport loss vs ring drops, finally distinguishable); drop events get red notches on the replay scrub track beside markers, plus a one-time live toast.
- `?profile=1` wraps tick/draw/paintStats/ingest in `performance.mark`/`measure` with a rolling breakdown tile.
- New wire fields rendered: horizontal wheel ticks, cumulative abs-frames tile, multi-device badge, and a desktop-mode cursor minimap in the desk panel (a live correctness check on integration).
- DPR-change listener re-sizes canvases when the window moves to a different-scaling monitor.

The demo recording gained new-format lines (including a deliberate seq gap to exercise loss detection); the old-format recordings are kept as the backward-compat fixtures and load correctly.

## Analyze (crates/analyze)

All 21 findings fixed (134 tests, clippy clean). Measured on a synthetic 3-hour /
10.8M-cell / 814k-event fixture: full analysis in 730ms, loader at 88ms for a
32MB file.

**Memory/perf at scale**
- The event vector is no longer cloned (`prepare` takes the session by value): −192MB at 8M events.
- The 1ms grid is now run-based sparse (active runs padded by the filters' support, so Savitzky–Golay and the tremor boxcar are *provably identical* to the dense version — parity-tested bit-exact per cell): 562MB dense → 358MB on the bursty bench fixture, more on real idle-heavy sessions.
- Both quadratics eliminated: flick→click matching is a monotonic two-pointer; pre-click movement lookup uses per-run reverse tables (O(log runs)) instead of cell-by-cell backward walks. Parity tests against the old behavior.
- Percentiles sort once (`sort_unstable_by(f64::total_cmp)`, no scratch allocation, no panic branch); kinematics derivatives are fused per-run (nothing session-length materialized); Welch/Goertzel runs on a 20:1 decimated 50Hz residual (~40× less work, tremor ground-truth tests unchanged); loader reserves capacity from file size, reuses one line buffer, borrow-deserializes batches, and interns game names; CSVs/JSON stream through `BufWriter`.

**Observability/provenance**
- Reports carry `analyzer_version`, `generated_utc_us`, `compute_ms`, grid cell counts, and per-phase timings; a final `analysis complete total_ms=` line closes every run. JSON schema bumped to `telemouse-analyze/2`.
- New data-quality checks: `seq_no` gap detection (lost batches), batch-latency p50/p99, dominant-game share (warn <80%), abs-frame totals, device list with multi-device warning, anchor uncertainty, and `locked_fraction` (warn <90%) with `--locked-only` to exclude desktop-mode spans from aim-space metrics.
- Grid truncation is now honest: rates use the analyzed span as denominator and the fake final-second spike is gone.

**Plan-metrics gaps closed**
- Marker segmentation (`--split-by-marker`): per-interval sub-reports between markers — the plan's round/clutch segmentation, live.
- Per-minute table (fatigue/warmup substrate): distance, speed, clicks, flicks, overshoot, tremor RMS, path efficiency per minute, in JSON + `per_minute.csv` + a rendered fatigue-curve table.
- Repositioning-lift inference (drift → gap → snap-back over movement segments, thresholds as documented `Params`).
- Longitudinal CLI: `report --json-dir` caches per-session reports (invalidated on version, mtime, *and* params changes), `trend` emits one row per session across a directory (table/CSV/JSON), `list --json`, and all 20 detector parameters are now CLI flags (was 3).
- Accel/jerk reported in cm and degrees alongside counts.

**Profiling**
- Criterion benches over the hot math at 1M/10M cells (savgol ≈ 203 Melem/s), `report --timing` phase table, and the workspace `profiling` profile for flamegraphs.

Remaining catalog items (aim-space/desk-space heatmaps, cross-session warmup
averaging) are unlocked by `trend`/`--json-dir` and remain future work.

## CPU pass — 2026-08-25

Goal: halve the CPU of the capture+viz pair. Measured with a purpose-built
harness (SendInput at 1kHz for 30s, a WebSocket client draining the bridge,
`QueryThreadCycleTime` per thread — Windows' tick-sampled thread times were
too coarse to see the deltas). Baseline at 1kHz: capture 4.08% of a core
(T1 3.16, T2 0.83, T3 0.10), viz 0.44%; total **4.52%**. Final: capture 1.72%
(T1 1.39, T2 0.31, T3 0.02), viz 0.46%; total **2.18%** (−52%). Idle capture
0.136% → 0.024%.

| Finding | Resolution |
|---|---|
| T1 spent ~28µs of kernel CPU per report, all inside the raw-input read (`GetRawInputData`, ~80µs wall). Skipping `DefWindowProc`, bypassing `DispatchMessage`, pinning the thread, a non-message-only window: no effect. `GetRawInputBuffer` costs the same *per call* — the cost is per read, not per report. | **Fixed** — T1 waits on `MsgWaitForMultipleObjectsEx`, sleeps `batch.coalesce_ms` (default 2, max 10, validated), then drains with one `GetRawInputBuffer`; non-input messages go through `PeekMessage`. 1/2/4ms measured at 2.22/1.39/0.87% for T1. Timestamps inside a drain: first report exact (the wake), the rest spaced by a per-drain interval estimator (`DrainStamper`, pure, tested), clamped to the drain time. Analyzer on a 1kHz recording: 60% ≤1ms / median 1.00ms / p99 1.25ms coalesced vs 52% / 1.00 / 1.29 exact. `SessionConfig.coalesce_ms` records the window. |
| T1 unparked T2 on *every* report; T2 did a wake→pop→park cycle per report (0.83%). | **Fixed** — T2 is only woken on the first event of an empty batch, then sleeps out the batch window and drains in bulk (0.31%; ring high-water ~45 instead of 1). |
| Idle: T2 woke every 25ms with nothing open; T3 `stat`ed `telemouse.toml` four times a second. | **Fixed** — idle park is 1s (the sink tick); markers, config changes and shutdown wake T2 explicitly. Config mtime checked every 2s. |
| viz bridge ~0.45% at 40 datagrams/s | **Left** — a single-thread runtime and a substring tag probe instead of the serde probe were both measured at zero gain; the cost is the recv/send syscalls. |
| The benchmark host had a defunct older `telemouse.exe` (shipping thread dead, still a `RIDEV_INPUTSINK` listener) during every run. | Noted — it received the same synthetic input and burned the same ~28µs/report, which is independent confirmation of the per-read cost; comparisons above are consistent because it was present throughout. |
| Binary wire schema (protobuf/flatbuffers/custom) | Plan says "once stable". The tagged `Envelope` JSON seam is intact and the skip-zero-fields change bought ~35% for free. Revisit when session files or Kafka volume actually hurt; a `RecordingReader` abstraction in core should land first so the loader is format-agnostic. |
| JSONL sink on its own thread | A stalled disk can still delay the UDP path within a flush cycle; flush timing is now measured (`jsonl_flush_us_max`), so there's data to justify the thread if it ever shows stalls. |
| timeBeginPeriod / timer-resolution changes | **Explicitly rejected.** Verified on this machine (and in Rust 1.98's std source): `thread::sleep` uses high-resolution waitable timers on Windows 10 1803+; 3ms sleeps measure ~3.8ms. Raising the system-wide timer tick would cost power for zero benefit. (The 2026-08-28 latency pass below sidesteps the overshoot per-thread instead, with T1's own `CREATE_WAITABLE_TIMER_HIGH_RESOLUTION` timer.) |

## Latency pass — 2026-08-28

A follow-up three-way audit (capture, core+profiles, viz) hunted what the CPU
pass left on the table, this time optimizing for tail latency and steady-state
allocation rather than mean CPU. Verified non-issues are listed at the end;
everything below is implemented (all tests green, clippy clean).

| Finding | Resolution |
|---|---|
| The lost-wakeup race between T1's relaxed `parked` load and T2's park was documented as "a slightly late flush" — but on the empty-ring branch the park timeout is `IDLE_PARK` = 1s, so a lost wake could hold the first event of a burst for up to a second. | **Fixed** — two-stage idle descent: after a drain leaves the ring empty, the first park keeps the 25ms batch-window timeout; only a park that *times out* with the ring still empty escalates to the 1s idle park. A lost wake now costs at most one batch window. Decision logic is a pure `next_park_timeout`, unit-tested. |
| `thread::sleep(coalesce_ms)` overshoots ~0.5–0.8ms on this machine (the CPU pass's own 3ms→3.8ms measurement), paid on **every** drain on top of the configured window; a quit/hotkey posted mid-window also waited it out. | **Fixed** — T1 arms one process-lifetime `CREATE_WAITABLE_TIMER_HIGH_RESOLUTION` waitable timer (plain-timer, then `thread::sleep` fallbacks; the resolution obtained is logged once) and waits it via `MsgWaitForMultipleObjectsEx`, masked `QS_ALLINPUT & ~QS_RAWINPUT` so arriving reports don't defeat the coalescing. Hotkeys/config/quit now interrupt the window instead of waiting it out. Expected ~±50µs vs ~+800µs; re-measure with the cycle harness. |
| T2 allocated three times per batch beyond the reused serialize buffer: `Batcher::take` surrendered a fresh ~10.75KB Vec 40×/s, and `build_batch` cloned `session_id` and `game` Strings per batch. | **Fixed** — core gained serialize-side borrowing mirrors `BatchView<'a>`/`EnvelopeView<'a>` (byte-parity with `Envelope::Batch` asserted by test) plus `Batcher::{events, first_qpc, reset}`; the flush path now serializes borrowed views into the reused buffer and `reset()`s the Vec in place. The shipping path is steady-state zero-allocation; shipping.rs's duplicate `first_qpc` mirror is gone. |
| Kafka path copied each payload twice (`Arc::from` on T2, then `.to_vec()` for rskafka's `Record`) with four allocations per envelope. | **Fixed** — `KafkaJob` owns `Vec<u8>`; buffers move through the channel into `Record`. One copy total. |
| `SharedContext::get()` was the last lock (`Mutex<Arc<_>>`) on T2's per-batch path. | **Fixed** — `arc_swap::ArcSwap<ContextSnapshot>`: lock-free `load_full()`/`store()`, same API surface. |
| A T2 (shipping) panic left a zombie agent: `capture_alive` watched T1 only, `let _ = t2.join()` discarded the payload, and the process exited 0 while T1 captured into a ring nobody drained. | **Fixed** — `shipping_alive` drop-guard flag mirrors `capture_alive` (guard-based, so panics are detected too); all joins log downcast panic payloads at error and the process exits nonzero. Found while evaluating `panic="abort"` — which stays **rejected** (it would forfeit the ordered teardown for ~zero perf gain). |
| `EnvelopeEncoder` UTF-8-validated the ~20KB payload twice per batch. | **Fixed** — String-backed buffer, validated exactly once in `encode`; `payload()` is a free borrow. No unsafe. |
| TCP_NODELAY was never set on the viz WebSocket connections (axum 0.8 removed `tcp_nodelay`; tokio/hyper don't set it). One small unidirectional frame every 25ms is the worst case for Nagle + delayed ACK — worst-case tens of ms of intermittent hold-back, invisible to the bridge histogram (which ends at UDP arrival; only the page's latency HUD sees this hop). | **Fixed** — `NoDelayListener` wrapper (axum 0.8 custom-`Listener` pattern) sets `set_nodelay(true)` per accepted connection, warn-once on failure, unit-tested. |
| Bridge copied each accepted datagram three times (String in `classify_datagram`, `Arc::from` in `publish_at`, `Utf8Bytes::from` per client at send). | **Fixed** — `Frame` is now `axum::extract::ws::Utf8Bytes` (Bytes-backed, refcounted), built once at classification; broadcast and per-client sends are refcount bumps. One payload copy per datagram regardless of client count. |
| `QpcAnchor::qpc_to_utc_us` did an i128 division per call — once per event in analyze's `prepare` (~814k calls on the bench fixture); `qpc_freq` is runtime so LLVM can't strength-reduce it. | **Fixed** — exact fast path for the ubiquitous 10MHz frequency (`dticks / 10`, bit-identical under i128 truncation, parity-tested for ±dticks and non-10MHz frequencies). |
| OBS-mode HUD constructed an `Intl.NumberFormat` per `toLocaleString()` call at 10Hz, and HUD text writes could in principle invalidate outside layout. | **Fixed** — one cached formatter; `contain: layout paint style` on `.hud`. |
| `lto = "fat"`, `panic = "abort"`, `opt-level` tuning, per-package profile overrides | **Evaluated and rejected** — the workload is syscall-dominated (~28µs kernel CPU per raw-input read); fat LTO's cross-crate inlining candidates are tiny and already handled by thin LTO + `codegen-units=1`. Rationale documented next to the profiles in the root `Cargo.toml`, with `-C target-cpu=znver3` noted as a documented opt-in for `telemouse-analyze`'s SIMD math only (benchable via the existing Criterion benches), not forced workspace-wide. |

Verified non-issues (checked, already optimal): T1 is genuinely
zero-allocation on the per-report path (drain buffer, `DrainStamper`, ring
push, relaxed-store counters all confirmed; the invariant's wording was
tightened to "per-report path" — hotkeys and first-sight device registration
are the rare, non-per-report exceptions); `RawEvent` is 24B/align-8 with no
reordering win and `Batch` exactly 2 cache lines; no `Mutex` reachable from
T1; T1↔T2 false sharing absent (`T1Counters` layout-asserted); sink order
already favors UDP; broadcast isolates slow WS clients; UDP recv buffer
reused; serde_json already uses itoa/ryu; per-event `pop()` chunking
(`read_chunk`) only pays above ~4kHz and stays deferred until such a device
exists.

## CPU pass 2 — 2026-08-29

Goal set by the user: at least a 70% cut in telemouse's CPU while playing,
and less in-game hitching. Measured with the harness now checked in under
`tools/cpubench` (SendInput at 1 kHz for 30 s, one WebSocket drain standing
in for the dashboard, an HTTP poller standing in for the control-panel page
every 2 s, `QueryThreadCycleTime` per thread). The metric is the **whole
stack**: capture + viz + ctl, as the user actually runs it. Baseline on the
tree as of that morning: **2.57% of a core loaded** (capture 1.69 = T1 1.39
/ T2 0.28 / T3 0.03, viz 0.42, ctl 0.46), **0.29% idle** (ctl 0.25). Final,
same harness: **0.76% loaded (−70%)** — capture 0.43 = T1 0.23 / T2 0.18 /
T3 0.03, viz 0.24, ctl 0.09 — and **0.09% idle (−69%)**. The tables and
every intermediate run are in [BENCHMARKS.md](BENCHMARKS.md).

| Finding | Resolution |
|---|---|
| The first CPU pass attributed T1's cost to the raw-input *read* (~28 µs per call). Experiments this time separated the two halves: a plain `WaitForSingleObject` instead of `MsgWaitForMultipleObjectsEx` inside the window saved 0.3%; skipping the queue wait altogether while reports keep coming (waiting on the timer alone) took T1 from 1.41% to 0.50% at the same 2 ms window; a 16-report buffer instead of 256 changed nothing. So the cost is being **woken by the raw-input queue** (~27 µs of kernel CPU per wake), not the read (~15 µs per drain including the timer wake). | **Fixed** — T1 waits on the message queue only while the mouse is still. A burst's first report wakes it (exact stamp); it then arms one periodic high-resolution timer at `coalesce_ms + 1` and drains on every tick until a drain comes back empty, then cancels the timer and returns to the queue. Messages (hotkey, quit, display change) are handled after the next drain, ≤ one window late; the mid-window `pump_non_input_messages` path is gone. At 1 kHz: 2 ms → 0.45%, 4 → 0.33%, 8 → 0.22% (cost ∝ drains/s). |
| With cadence drains nothing observes an arrival, and anchoring each drain at "previous read + one interval" left a 2 ms gap whenever a period held one report fewer: p99 inter-event interval 1.59 ms vs 1.11 ms before. | **Fixed** — `DrainStamper::spread`: a cadence drain's `n` reports are spread evenly over the period since the previous read, the last at the read time. Bounds the interval error (a short period changes every spacing by a fraction instead of one double gap) and is monotonic across drains by construction. Analyzer on the harness recording at the 8 ms default: median 1.00 ms, **p99 1.08 ms**, no gaps > 10 ms. Pure, tested. |
| Every batch costs ~150 µs of kernel CPU across the pipeline whatever it holds: ~47 µs for the capture agent's UDP send, ~30 µs for the bridge's receive, ~72 µs per WebSocket client (loopback send micro-benchmark in `tmbench`: TCP and UDP both ~47 µs per send on this box, independent of size; a `current_thread` runtime and a blocking UDP thread outside tokio were both measured at zero gain — the library overhead is ~25 µs of the 72, the rest is the kernel). At 40 batches/s that was 0.6% of a core with one browser, +0.27% per additional browser. | **Changed default** — `batch.window_ms` 25 → 50 (20 batches/s): T2 0.28 → 0.18, viz 0.42 → 0.24 with one client. Live latency floor 26 → 51 ms p50; recordings and analysis are unaffected (batch boundaries carry no analytic meaning). `25` remains a one-line config change and is documented as the trade. The page now floors its live buffer at one observed batch span + 10 ms (`engine.effectiveLiveBuffer`) so a longer window can never turn into a visible stutter, whatever the slider or `[viz.obs] buffer_ms` says. |
| `batch.coalesce_ms` default 2 → 8 | **Changed default** — with cadence pacing T1's cost is per drain, so the window is the knob: 8 ms is 111 drains/s (0.22%). What it costs: a pause shorter than ~9 ms inside a burst is smoothed over, and in-burst stamps are reconstructed rather than observed (they were mostly reconstructed at 2 ms too).
