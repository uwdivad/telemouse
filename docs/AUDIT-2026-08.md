# Audit — August 2026: findings and resolutions

A three-way code audit (capture, viz, analyze/core) reviewed the codebase for
observability, logging, tracking gaps, profiling readiness, and CPU/performance.
~80 findings were produced; this document records what was fixed and what was
deliberately deferred. Line references are to the pre-fix code.

## Workspace & core (shared contract)

| Finding | Resolution |
|---|---|
| No profiling affordance: release builds had no debug symbols | **Fixed** — `[profile.profiling]` (release + symbols) and `codegen-units = 1` on release in the root `Cargo.toml`. Build with `cargo build --profile profiling` for flamegraphs. |
| Config accepted typo'd keys silently (`mouse_dpi` → every cm metric quietly wrong) | **Fixed** — `deny_unknown_fields` on `AppConfig` and every sub-struct; unknown keys are now a parse error. |
| No config validation (negative CPI → inf cm; `window_ms=0` → datagram per event; `max_events=0` → panic) | **Fixed** — `AppConfig::validate()` runs on load: positive CPI/sens/coeffs, window ≥ 1ms, `1 ≤ max_events ≤ MAX_EVENTS_PER_BATCH`, `ring_capacity ≥ max_events`, brokers non-empty when Kafka enabled. |
| Multiple pointing devices indistinguishable (trackpad silently pollutes CPI-derived metrics — unrecoverable retroactively) | **Fixed (wire)** — `SessionConfig.devices: Vec<String>` + `RawEvent.device_ix: u8`. Capture populates them; old recordings default to empty/0. |
| Horizontal wheel (`RI_MOUSE_HWHEEL`) silently discarded | **Fixed (wire)** — `RawEvent.wheel_h: i16`. |
| Absolute-motion frames counted locally but never recorded on the wire | **Fixed (wire)** — `Batch.abs_frames_since_last: u32`. |
| Anchor taken from two unbracketed clock reads, uncertainty unrecorded | **Fixed (wire)** — `SessionConfig.anchor_uncertainty_us` records the QPC/UTC/QPC sandwich half-width; capture measures it. |
| JSON wire cost ~71 B/event; `null`s serialized for absent options | **Improved** — zero-valued `buttons`/`wheel`/`wheel_h`/`device_ix` and `None` cursor/game fields are omitted; a typical motion-only event is now ~45 B. Consumers treat missing fields as 0/absent. Full binary schema remains deferred (below). |
| Worst-case batch could exceed a UDP datagram with the new fields | **Fixed** — `MAX_EVENTS_PER_BATCH` 512 → 448; the core test asserting a worst-case batch fits the datagram budget still enforces this. Cap only binds above ~17KHz. |

## Capture agent (crates/capture)

All 22 findings fixed (97 tests, clippy clean).

**Operational correctness**
- UDP `WSAECONNRESET` (viz not running — the default state) no longer warns per batch: counted as `udp_unreachable`; all sink failures rate-limited to one warn per sink per 10s with a suppressed count.
- Dead-capture detection: `capture_alive` flag — if T1's message loop dies, the agent shuts down loudly instead of running as a zombie. `idle_for_s` in stats distinguishes "idle mouse" from "capture broken".
- Both shutdown hangs fixed: HWND handoff via atomics with a `PostThreadMessageW` fallback; Kafka drain bounded by a 3s timeout with an abandoned-envelope count.

**Tracking (previously unrecoverable)**
- Devices enumerated at startup into `SessionConfig.devices` (index 0 reserved as "unknown"); every event carries `device_ix`, so a trackpad can no longer silently pollute CPI-derived metrics.
- Horizontal wheel captured (`wheel_h`); absolute-motion frames now on the wire per batch; pointer-lock transitions logged.
- Anchor taken as a QPC/UTC/QPC sandwich with recorded uncertainty; drift re-measured every 60s (logged in ppm, `anchor_drift_us=N` marker emitted past ±200µs).
- Config-file mtime watch: mid-session changes are validated, diffed into the log, and recorded as a `config_changed` marker; `WM_DISPLAYCHANGE` refreshes monitor info.

**Observability**
- Zero-allocation 32-bucket log2 latency histogram: `capture_to_ship_us` p50/p99 (and ship-tail p99) in the 5s stats line — the pipeline's first latency metric.
- Ring high-water sampling (early warning long before drops), JSONL flush-time max, `udp_oversized`, edge-triggered Kafka-drop warnings (0→dropping and recovery, never per-drop).
- The 5s stats line is now 22 structured tracing fields (including `session_id`) instead of one pre-formatted string.

**CPU**
- T2 parks and is unparked by T1 on the ring's empty→non-empty edge (one relaxed load per event on the hot path); park timeout tracks the remaining batch window (0.5–25ms), which also improves first-event latency. Main thread and T3 wait on a shutdown condvar — idle wakeups largely eliminated.
- Context snapshot moved out of the 333/s loop into the flush path and made `Arc` (no per-iteration mutex + String clone).
- T1's counters are cache-line-isolated (`#[repr(align(64))]`, layout-asserted by test) with relaxed stores instead of RMWs.
- Serialize-once: one JSON encode per batch into a reused buffer shared by all sinks; the Kafka channel carries `Arc<str>` payloads.
- Kafka: zstd compression + 25ms linger via the batch producer (produces coalesced through a bounded `JoinSet` so the linger actually batches).
- T1 runs at `ABOVE_NORMAL` priority; process opts out of EcoQoS power throttling so P/E-core parking can't starve capture.
- Foreground process name re-resolved only on PID change (~14,400 handle opens/hour → ~one per alt-tab).

## Viz (crates/viz)

All 22 findings fixed (52 tests, clippy clean; behaviors verified in a live browser session).

**Bugs**
- Hidden-tab memory leak: ingest hard-caps the event backlog (~2× the live window), a `setInterval` trim survives rAF suspension, and catch-up is bounded per tick — verified: 150k events ingested with a hidden tab stayed bounded, and returning drains without freezing.
- Capture-agent restart: a `session` envelope with a new id fully resets the engine before adopting the new anchor (no more mixed timelines).
- Scrubbing: forward seeks never re-integrate; backward seeks restore from 10s integrator checkpoints — verified bit-identical to full re-integration, cost now bounded by checkpoint spacing rather than session length.

**Latency (measured for the first time, and improvable)**
- End-to-end latency tile in the page (`anchor.utc_us` now used), bridge-side p50/p99 in the log, `/api/stats`, and a pushed `viz_stats` frame — observed loopback bridge latency p50 0.2ms.
- The 55ms smoothing buffer is now a 10–200ms slider (persisted); canvases use `{alpha:false, desynchronized:true}`, removing a compositor frame.
- New stat tiles: lag-behind-live (red > 250ms) and render FPS (red when below ~0.8× refresh).

**CPU**
- Dirty-flag rendering: zero draws when nothing changed (verified 240 idle frames → 0 draws) — previously the page full-redrew both canvases every frame forever.
- Event timeline converted to typed-array columns and trails to fixed ring buffers: no per-event object churn, no per-frame `splice`.
- Tokio trimmed to 2 worker threads (and features narrowed from "full"); transport-bar DOM writes throttled to 100ms; broadcast channel 1024→256 with `Arc<str>` payloads and a tag-only serde probe instead of full envelope parses.

**Scale**
- `/api/session/{id}` streams from disk (with Content-Length) instead of reading whole files into memory; the page loads replays via a streaming reader with progress, feeding typed arrays directly — hour-long sessions no longer risk tab OOM.

**Observability/tracking**
- Bridge health visible in the page (datagrams/s, parse errors red when nonzero) without polling; first rejected datagram logged at warn with a sanitized payload prefix, rate-limited per reason.
- `seq_no` gaps tracked as a separate "lost batches" stat (transport loss vs ring drops, finally distinguishable); drop events get red notches on the replay scrub track beside markers, plus a one-time live toast.
- `?profile=1` wraps tick/draw/paintStats/ingest in `performance.mark`/`measure` with a rolling breakdown tile.
- New wire fields rendered: horizontal wheel ticks, cumulative abs-frames tile, multi-device badge, and a desktop-mode cursor minimap in the desk panel (a live correctness check on integration).
- DPR-change listener re-sizes canvases when the window moves to a different-scaling monitor.

The demo recording gained new-format lines (including a deliberate seq gap to exercise loss detection); the old-format recordings are kept as the backward-compat fixtures and load correctly.

## Analyze (crates/analyze)

All 21 findings fixed (134 tests, clippy clean). Measured on a synthetic 3-hour /
10.8M-cell / 814k-event fixture: full analysis in 730ms, loader at 88ms for a
32MB file.

**Memory/perf at scale**
- The event vector is no longer cloned (`prepare` takes the session by value): −192MB at 8M events.
- The 1ms grid is now run-based sparse (active runs padded by the filters' support, so Savitzky–Golay and the tremor boxcar are *provably identical* to the dense version — parity-tested bit-exact per cell): 562MB dense → 358MB on the bursty bench fixture, more on real idle-heavy sessions.
- Both quadratics eliminated: flick→click matching is a monotonic two-pointer; pre-click movement lookup uses per-run reverse tables (O(log runs)) instead of cell-by-cell backward walks. Parity tests against the old behavior.
- Percentiles sort once (`sort_unstable_by(f64::total_cmp)`, no scratch allocation, no panic branch); kinematics derivatives are fused per-run (nothing session-length materialized); Welch/Goertzel runs on a 20:1 decimated 50Hz residual (~40× less work, tremor ground-truth tests unchanged); loader reserves capacity from file size, reuses one line buffer, borrow-deserializes batches, and interns game names; CSVs/JSON stream through `BufWriter`.

**Observability/provenance**
- Reports carry `analyzer_version`, `generated_utc_us`, `compute_ms`, grid cell counts, and per-phase timings; a final `analysis complete total_ms=` line closes every run. JSON schema bumped to `telemouse-analyze/2`.
- New data-quality checks: `seq_no` gap detection (lost batches), batch-latency p50/p99, dominant-game share (warn <80%), abs-frame totals, device list with multi-device warning, anchor uncertainty, and `locked_fraction` (warn <90%) with `--locked-only` to exclude desktop-mode spans from aim-space metrics.
- Grid truncation is now honest: rates use the analyzed span as denominator and the fake final-second spike is gone.

**Plan-metrics gaps closed**
- Marker segmentation (`--split-by-marker`): per-interval sub-reports between markers — the plan's round/clutch segmentation, live.
- Per-minute table (fatigue/warmup substrate): distance, speed, clicks, flicks, overshoot, tremor RMS, path efficiency per minute, in JSON + `per_minute.csv` + a rendered fatigue-curve table.
- Repositioning-lift inference (drift → gap → snap-back over movement segments, thresholds as documented `Params`).
- Longitudinal CLI: `report --json-dir` caches per-session reports (invalidated on version, mtime, *and* params changes), `trend` emits one row per session across a directory (table/CSV/JSON), `list --json`, and all 20 detector parameters are now CLI flags (was 3).
- Accel/jerk reported in cm and degrees alongside counts.

**Profiling**
- Criterion benches over the hot math at 1M/10M cells (savgol ≈ 203 Melem/s), `report --timing` phase table, and the workspace `profiling` profile for flamegraphs.

Remaining catalog items (aim-space/desk-space heatmaps, cross-session warmup
averaging) are unlocked by `trend`/`--json-dir` and remain future work.

## Deliberately deferred

| Item | Why |
|---|---|
| `GetRawInputBuffer` batch-drain (the plan's 8KHz fallback) | At 1KHz the per-message path measures ~0.4% CPU with zero drops. The buffered path loses per-event timestamps (one QPC per drain), degrading the inter-event-interval data-quality metric — a real trade-off that should wait until an 8KHz mouse exists to test against. Ring high-water and capture→ship latency metrics now exist to signal when it's needed. |
| Binary wire schema (protobuf/flatbuffers/custom) | Plan says "once stable". The tagged `Envelope` JSON seam is intact and the skip-zero-fields change bought ~35% for free. Revisit when session files or Kafka volume actually hurt; a `RecordingReader` abstraction in core should land first so the loader is format-agnostic. |
| JSONL sink on its own thread | A stalled disk can still delay the UDP path within a flush cycle; flush timing is now measured (`jsonl_flush_us_max`), so there's data to justify the thread if it ever shows stalls. |
| timeBeginPeriod / timer-resolution changes | **Explicitly rejected.** Verified on this machine (and in Rust 1.98's std source): `thread::sleep` uses high-resolution waitable timers on Windows 10 1803+; 3ms sleeps measure ~3.8ms. Raising the system-wide timer tick would cost power for zero benefit. |
